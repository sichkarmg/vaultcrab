# Releasing

Vaultcrab follows [SemVer](https://semver.org/). While the version is 0.x, new features bump the
minor version and fixes bump the patch version. 1.0.0 is decided by the owner.

## Steps

1. **Release PR** from `main` (branch `chore/release-X.Y.Z`):
   - set `var version = "X.Y.Z"` in `cmd/vaultcrab/main.go`;
   - in `CHANGELOG.md` rename `## [Unreleased]` to `## [X.Y.Z] - YYYY-MM-DD`, add a new empty
     `## [Unreleased]` section and update the compare links at the bottom;
   - run `make release-check` (version in code, CHANGELOG section, free tag, clean tree, gofmt,
     vet, tests, all builds);
   - open the PR, wait for green `ci`, squash-merge.
2. **Tag** the merge commit on `main`:
   ```sh
   git switch main && git pull --ff-only
   git tag -a vX.Y.Z -m "Vaultcrab X.Y.Z"
   git push origin vX.Y.Z
   ```
3. **Draft.** `.github/workflows/release.yml` (on a macOS runner) checks that the tag matches the
   version in code, runs the tests and GoReleaser (`.goreleaser.yaml`), and creates a **draft
   pre-release**:
   - `vaultcrab_X.Y.Z_linux_amd64.tar.gz`, `…_linux_arm64.tar.gz` (static, no cgo),
     `…_darwin_amd64.tar.gz`, `…_darwin_arm64.tar.gz` (native, with cgo), `…_windows_amd64.zip`, each with
     `README.md`, `LICENSE`, `THIRD_PARTY_NOTICES.md`;
   - `checksums.txt` (SHA-256);
   - release notes generated by GitHub from the merged PRs.
4. **Verify** the draft: `scripts/release-verify.sh vX.Y.Z` downloads the assets, checks the
   checksums and archive contents, and runs `vaultcrab --version` and a TUI smoke start on the Linux
   Mint 20 and Windows test VMs.
5. **Publish as a pre-release** (never as "latest"):
   ```sh
   gh release edit vX.Y.Z --draft=false --prerelease --latest=false
   ```
   The owner tests on macOS and promotes the release to "latest".

## Rules

- Never delete or rewrite a published tag or release. If a release is broken, edit its notes, mark
  it clearly at the top, and fix it in a new patch release.
- The macOS and Windows binaries are not signed; the README says so.
- `bw` is never bundled.
- A local build of the release artifacts without GitHub: `make release` (`dist/vaultcrab-<os>-<arch>`
  and `dist/SHA256SUMS`), or `goreleaser release --snapshot --clean` (same archives as the
  workflow; check them with `VAULTCRAB_RELEASE_DIR=dist scripts/release-verify.sh vX.Y.Z-SNAPSHOT-…`).

## Toolchain updates

Dependabot updates Go modules and GitHub Actions. By hand: the Go version (`GO_VERSION` in
`ci.yml`, `go-version` in `release.yml`), `GOVULNCHECK_VERSION`, `GITLEAKS_VERSION` with its
`GITLEAKS_SHA256`, and the GoReleaser `version` in `release.yml`.
